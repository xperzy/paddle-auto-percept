# BEV特征的理解：

**什么是BEV特征？** 

- Bird’s Eye View特征，是指在自动驾驶感知领域中，将车辆周围的三维世界，投影到一个2维的鸟瞰图上进行表示的一种方式。鸟瞰图也可以叫做俯视图。例如下图中，所有红色框的部分，都可以称作是BEV特征。我们的目标也是学习这个特征，使得其中每个位置都包含有对应真实空间中的丰富语义信息。

![image.png](%E4%BB%8E%E9%9B%B6%E5%BC%80%E5%A7%8B%E5%AD%A6%20BEVFormer%20(1)%20-%20BEVFormer%20%E7%9A%84%E6%95%B4%E4%BD%93%E6%9E%B6%E6%9E%84%201c13135fac1780989e7af61b94dc2eaa/bc37b5e9-216c-4783-99c2-a79429c30b09.png)

- BEV特征可以通过深度学习算法，将不同的传感器的数据转换到BEV视角下的特征，能够帮助系统更好的理解周围的环境

举例来说，某一时刻在车上采集到的2D图像，通常是通过安装在车身的多个相机采集得到不同视角的图像。这些图像，可以根据3D空间中的点的位置进行投影、变换等操作，并通过深度学习算法，转换为BEV特征。这样就可以直接在BEV特性上，做具体的感知任务，例如目标检测等。**所以我们通常说的BEV，其实是BEV特征，是一个能和3D世界对应的特征图**。

**直观理解：**

- 基础版的BEV特征，就是预设了一个固定大小的特征图，比如 `[N, H, W, C]`，其中`N`是batch size，`C`是特征的维度。`H，W`表示特征图的大小，这个大小人为的设定与某个真实世界的范围相对应，例如，当前的BEV覆盖的范围是`100m x 100m` ，设定`H=200，W=200` ，那么每个BEV特征（一共H行W列，H*W个），就代表真实世界中`0.5m x 0.5m`2D空间的特征表达。
    - 也就是说，在BEV特征中，我们设置，使用一个`C`维的特征，表示某一位置大小为`0.5mx0.5m`的区域。位置是根据当前特征的下标，和真实世界的范围所对应的。
    - 有了BEV覆盖范围内，每个格子的特征表达，可以理解为，我们就有了一张“鸟瞰图”，只不过这张鸟瞰图的每个“像素”并不是RGB像素，而是一个需要经过网络学习的`C`维特征。
    - 有了BEV特征，也就有了当前覆盖范围内的信息，这些信息是通过网络将图像特征融合到BEV特征上来的，所以BEV特征通过“看”图像得到了特征，这些特征就可以进一步用来做具体的任务了，比如目标检测，分割，语义理解等等。

# BEVFormer的整体架构：

BEVFormer模型的输入是多视角的视觉图像，经过模型encoder和decoder结构，输出一个显式的BEV特征图，最后在特征图上，接任务头来完成预测。其中encoder部分，主要设计了两种不同的注意力结构：TSA，用来结合历史帧信息，SCA，用来结合多视角图像信息，以此来更好的学习BEV特征。而Decoder部分，则是通过自注意力和交叉注意力机制，将目标查询和BEV特征结合，最终完成从特征到目标的转换。**注意，论文中的示意图，主要画的是Encoder的部分，而Decoder没有将结构细节画出来，但其实Decoder本身也是一个多层Transformer结构，并且也使用了Self-Attention和Cross-Attention**。

**Encoder 部分**：

- **BEV Query**：在BEVFormer中，Encoder会设置一个**BEV Query**，这实际上是一个初始化的查询向量，它代表了BEV特征，只不过此时还没有学到任何东西。Encoder的作用是通过注意力机制将历史帧的BEV特征与BEV Query相结合，之后再将多视角图像特征与BEV Query相结合**。**
- **Temporal Self-Attention:** 用于将历史BEV特征和当前BEV查询相结合的注意力计算，结合部分BEVFormer采用了concat这样比较直接的操作，但需要注意的是，这里有很多实现细节，用于保证前后帧的BEV特征的对齐。

![image.png](%E4%BB%8E%E9%9B%B6%E5%BC%80%E5%A7%8B%E5%AD%A6%20BEVFormer%20(1)%20-%20BEVFormer%20%E7%9A%84%E6%95%B4%E4%BD%93%E6%9E%B6%E6%9E%84%201c13135fac1780989e7af61b94dc2eaa/image%201.png)

- **Spatial Cross-Attention**： 用于将图像特征和当前BEV查询相结合的注意力计算，这部分类似于DETR3D的计算，但用于特征采样的参考点位置，在BEVFormer中是基于BEV特征图生成的，也就是说，根据BEV特征图（本身具有空间意义）的位置，在各个视角的对应位置上，进行图像特征采样，用于计算当前点的注意力。也正是这一步，BEVFormer结构才获得了图像信息。这里，找到BEV的3D参考点在图像上的位置，会用到3D到2D投影相关计算。
    - 图中右边所示，彩色部分是各个视角的图像特征，中间格子是BEV特征。步骤是，首先在BEV特征上生成参考点位置，这些点是3D空间的具有位置信息的坐标点。其次，将这些点的3D位置，通过相机的内外参，坐标系转换等方式，投影到各个视角下找到对应的位置。最后，基于这些位置进行特征采样，并用于该3D点的特征注意力计算。输出是基于BEV的2D特征，所以会把这些3D点特征以及多个采样点进行合并。

![image.png](%E4%BB%8E%E9%9B%B6%E5%BC%80%E5%A7%8B%E5%AD%A6%20BEVFormer%20(1)%20-%20BEVFormer%20%E7%9A%84%E6%95%B4%E4%BD%93%E6%9E%B6%E6%9E%84%201c13135fac1780989e7af61b94dc2eaa/image%202.png)

- 这一过程的目标是将来自不同视角的信息、还有前帧的信息，编码进BEV Query中，最终使得BEV Query能够捕捉到整个场景的空间和时间信息。

**Decoder 部分**：

- **Object Query**：Decoder部分则设置了一个**Object Query**，这个查询向量是用来表示某个具体物体（障碍物）的特征。Object Query在经过Decoder的处理后，能够生成一个代表障碍物的特征表示。
- **自注意力（Self-Attention）**：Object Query之间的**自注意力机制**主要用于捕捉不同物体（或物体之间）之间的关系。自注意力的目的是让每个Object Query不仅能看自己，还能在一定程度上关注到与其他Object Query相关的上下文信息。这是为了提高模型对物体间相互关系的建模能力，尤其是在复杂环境中识别多个物体时尤为重要。
- **交叉注意力（Cross-Attention）**：Object Query接下来与BEV Query进行交叉注意力机制，目的是让Object Query能够有效地融合BEV特征，这样生成的Query特征不仅包含物体本身的信息，还能带有BEV中的空间信息和时间信息（例如，障碍物在场景中的空间分布、动态状态等）。
- 最终，经过Decoder处理的Object Query会得到一个包含了前帧和图像信息的物体级别特征，这个特征可以用来通过检测头（如分类器和回归器）进行物体检测任务的预测

**注意力部分：**

BEVFormer最重要的注意力部分，使用的是可变形注意力，这个可变形注意力机制，以不同的形式使用在Encoder的TSA、SCA，以及Decoder的Cross-Attention中。它最大的优势在于，通过灵活的采样策略来计算每个特征点的注意力，而不是依赖标准的全局注意力计算。这样，在计算过程中，模型只需要关注局部区域或个别关键点，节省大量计算量和内存。

具体来说，在**TSA**和**SCA**模块中，可变形注意力机制允许模型根据输入特征的不同位置进行灵活的采样，这使得模型能够在处理时动态选择重要区域而不是遍历所有区域。这种采样方式可以根据任务的需求进行调整，从而在保持性能的同时提高效率。

在**Decoder**中的Cross-Attention部分，可变形注意力使得Object Query和BEV Query之间的交互更加高效。通过对每个查询点周围的局部区域进行动态调整，模型能够更精确地融合物体级别的特征和BEV特征，避免了传统全局注意力计算中的冗余操作。
